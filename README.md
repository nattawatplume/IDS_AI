# Market IDS

ระบบเฝ้าดูตลาดคริปโต แล้วเตือนเมื่อการซื้อขายดูผิดปกติทางสถิติ เช่น จำนวนการซื้อขายและราคาพุ่งขึ้นผิดธรรมชาติในเวลาสั้นๆ ซึ่งอาจเป็นสัญญาณของการปั่นราคา

ลองนึกภาพกล้องวงจรปิดของตลาด กล้องไม่ได้จับคนร้าย แต่บอกว่า "ช่วงเวลานี้แปลกนะ ลองเข้าไปดู" พร้อมตัวเลขที่เป็นหลักฐานและคำอธิบายภาษาไทย

โครงงานนี้ทำเพื่อการศึกษาในวิชา CPE102 และใช้เฉพาะข้อมูลสาธารณะของ Binance

## ระบบนี้ไม่ทำอะไร

- ไม่ซื้อขายแทนใคร ไม่มีโค้ดส่งคำสั่งซื้อขาย และไม่ใช้ API key
- ไม่แนะนำการลงทุน และไม่ทำนายราคา
- ไม่กล่าวหาใคร การเตือนไม่ได้พิสูจน์ว่ามีการปั่นราคา เพราะข่าวใหญ่ก็ทำให้ตลาดพุ่งแบบนี้ได้

## หลักการทำงาน

ระบบเรียนรู้ก่อนว่าช่วงปกติของแต่ละเหรียญเป็นอย่างไร แล้วเทียบว่าตอนนี้ต่างจากปกติมากแค่ไหน

```text
ข้อมูลการซื้อขาย
  -> สรุปเป็นตัวเลขทุก 10 วินาที
  -> เทียบกับช่วงปกติของเหรียญนั้น
  -> ตัวตรวจจับ 3 แบบช่วยกันดู
  -> รวมคะแนนเป็นค่าเดียว แล้วเทียบกับเกณฑ์
  -> รวมช่วงที่เกินเกณฑ์ติดกันเป็นการเตือนหนึ่งครั้ง
  -> เขียนคำอธิบายภาษาไทย แล้วส่งให้หน้าจอ
```

ตัวตรวจจับ 3 แบบเก่งกันคนละด้าน

| แบบ | วิธีคิด |
|---|---|
| กฎ | จับรูปแบบที่รู้จักอยู่แล้ว เช่น จำนวนการซื้อขายพุ่งพร้อมราคาพุ่ง |
| สถิติ | จับค่าที่สูงหรือต่ำกว่าปกติมาก |
| AI | เรียนจากช่วงปกติ ถ้าเจอรูปแบบที่ไม่คุ้นก็ให้คะแนนความผิดปกติสูง |

## โหมดการใช้งาน

| โหมด | ความหมาย |
|---|---|
| สด (live) | รับข้อมูลจาก Binance แล้วตรวจแบบเรียลไทม์ |
| ย้อนดู (replay) | เล่นข้อมูลวันเก่าซ้ำเหมือนดูวิดีโอ หยุดหรือกรอได้ |
| จำลองเหตุการณ์ (Red-Team) | ใส่รูปแบบการปั่นราคาลงในข้อมูลเก่า เพื่อดูว่าระบบจับได้ไหม ทำได้เฉพาะโหมดย้อนดูหรือจำลอง ระบบจะปฏิเสธถ้าสั่งในโหมดสด |

## เริ่มใช้งานเร็ว (เดโม)

ต้องมี Python 3.13 และ [uv](https://docs.astral.sh/uv/) แล้วรันจากโฟลเดอร์ของโปรเจกต์

```bash
uv sync
uv run idsai demo-pack
uv run idsai serve --mode replay
```

1. `uv sync` ติดตั้งโปรแกรมเสริมทั้งหมด
2. `uv run idsai demo-pack` โหลดข้อมูลชุดเล็กจาก Binance Vision (วันที่มีบันทึกการปั่นราคา 3 วัน และวันปกติ 20 วันของเหรียญเดียวกัน) แล้วฝึกโมเดลเก็บไว้ที่ `data/demo/` ใช้เน็ตครั้งเดียว รันซ้ำได้ วันที่โหลดแล้วจะข้าม
3. `uv run idsai serve --mode replay` เล่นวันแรกของชุดเดโมซ้ำ เริ่ม 30 นาทีก่อนเวลาในบันทึก ที่ความเร็ว 60 เท่า แล้วเปิด API ที่ `http://127.0.0.1:8800` กด Ctrl+C เพื่อหยุด

ตอนนี้ยังไม่มีหน้า Dashboard และยังไม่มีตัวเลขผลการตรวจจับบนข้อมูลจริงแบบเต็มรูปแบบ

## คำสั่งทั้งหมด

ทุกคำสั่งรันแบบ `uv run idsai <คำสั่ง>` ดูรายละเอียดได้ด้วย `uv run idsai <คำสั่ง> --help` ถ้าสำเร็จจะจบด้วยรหัส 0 ถ้าข้อมูลไม่พอหรือใช้คำสั่งผิดจะจบด้วยรหัส 1 พร้อมบอกว่าต้องรันอะไรต่อ

| คำสั่ง | ทำอะไร |
|---|---|
| `labels` | เขียนบันทึกเหตุการณ์ปั่นราคาจริงลงเครื่อง (Sapienza เสมอ และ Hu et al. ถ้าโหลดไฟล์ไว้แล้ว) |
| `labels --align` | ตรวจว่าเวลาในบันทึกตรงกับช่วงที่มีการซื้อขายมากที่สุดจริงไหม พิมพ์ฮิสโทแกรม ถ้าคลาดเกิน 120 วินาที (ค่ามัธยฐาน) หรือวัดไม่ได้เลย จะจบด้วยรหัส 1 |
| `download --split research` | โหลดทุกวันที่งานวิจัยต้องใช้ (วันที่มีบันทึก วันก่อนหน้า และวันปกติที่เป็นตัวเลือก) |
| `download --symbols S --days N` | โหลด N วันล่าสุดของเหรียญที่ระบุ และวันก่อนหน้าวันแรก |
| `download --symbols S --day D` | โหลดวัน D และวันก่อนหน้า |
| `train [--profile research\|live] [--seed N]` | ฝึกโมเดลและตั้งเกณฑ์การเตือน เก็บที่ `models/research/` หรือ `models/live/` |
| `eval --experiment NAME\|all --seeds 0,1,2,3,4` | รันการทดลอง บันทึกผลลง `data/research.duckdb` |
| `report` | สร้างรายงานจากการทดลองทุกครั้ง ได้ `data/report.json` และ `data/report.md` |
| `demo-pack` | สร้างชุดเดโมเล็ก (ดูด้านบน) |
| `serve --mode replay [--symbol S --day D] [--speed 60]` | เล่นข้อมูลเก่าซ้ำ ไม่ระบุวัน = เล่นชุดเดโม |
| `serve --mode live` | ตรวจแบบสด ต้องรัน `download --symbols ... --days 8` และ `train --profile live` ก่อน |

ลำดับงานวิจัยเต็มรูปแบบ: `labels` → `download --split research` → `labels --align` → `train` → `eval` → `report`

`serve` เปิดที่ `127.0.0.1` พอร์ต `8800` (เฉพาะเครื่องตัวเอง) ถ้าใช้ `--host` อื่นต้องเปิดระบบล็อกอินก่อน (ดูหัวข้อถัดไป) ไม่เช่นนั้น `serve` จะไม่ยอมเริ่ม และ API รับเฉพาะคำขอที่ส่งมาถึงชื่อ `127.0.0.1`, `localhost` หรือ host ที่ระบุเท่านั้น

## ระบบล็อกอิน

ปกติ `serve` ไม่ต้องล็อกอิน (ใช้ได้เฉพาะเครื่องตัวเอง) ถ้าจะเปิดให้เครื่องอื่นเข้า ต้องเปิดระบบล็อกอิน:

1. สร้างผู้ดูแลก่อน: `uv run idsai user add <ชื่อ> --role admin` (ระบบถามรหัสผ่านแบบซ่อน ยาวอย่างน้อย 10 ตัว ไม่รับรหัสผ่านทางบรรทัดคำสั่ง)
2. เปิดด้วย `uv run idsai serve --auth ...` หรือใส่ `auth.enabled: true` ใน `configs/default.yaml` (`--no-auth` ปิดชั่วคราว)
3. สิทธิ์มี 3 ระดับ: `viewer` ดูอย่างเดียว, `analyst` ดูและบันทึกผลการตรวจกับยิงทดสอบได้, `admin` ทำได้ทุกอย่างและดูหน้า "กิจกรรม" (บันทึกการเข้าสู่ระบบและการจัดการบัญชี)
4. จัดการบัญชี: `uv run idsai user list | add | passwd | role | disable | enable` ชื่อ `cli` และ `local` ใช้เป็นชื่อในบันทึกกิจกรรม จึงตั้งเป็นชื่อผู้ใช้ไม่ได้

บล็อก `auth:` ในไฟล์ค่าตั้ง: `enabled` (เปิด/ปิด), `cookie_secure` (ตั้งเป็น `true` เมื่อเปิดผ่าน HTTPS), `remember_days` (อายุเมื่อติ๊กจำฉัน), `session_hours` (อายุปกติ) บล็อกนี้ไม่นับใน `config_hash` เพราะไม่กระทบโมเดลหรือผลการตรวจ

คำสั่ง `user` ต้องหยุด `serve` ก่อน เพราะฐานข้อมูลเปิดได้ทีละโปรแกรม ถ้า `serve` ยังรันอยู่จะขึ้นข้อความให้หยุดแล้วลองใหม่

```bash
uv run pytest
```

ชุดทดสอบไม่ใช้เน็ตและใช้เวลาหลายนาที บน Windows ควรเก็บโปรเจกต์ไว้ในโฟลเดอร์ที่ path ไม่ยาวมาก เพราะ path ที่ยาวเกิน 260 ตัวอักษรอาจทำให้เขียนไฟล์ข้อมูลหรือแคชไม่สำเร็จ

## ข้อจำกัด

- โหมดสดต้องอุ่นเครื่องก่อน แถวข้อมูลแรกมาราว 30 นาทีหลังเชื่อมต่อ ค่าเทียบกับช่วงปกติใช้ได้ทันทีถ้าข้อมูลย้อนหลังที่โหลดมายังใหม่พอ (ครอบคลุมอย่างน้อย 6 ชั่วโมงของ 24 ชั่วโมงล่าสุด) ไม่อย่างนั้นต้องรอราว 6.6 ชั่วโมง
- API ไม่มีระบบล็อกอิน จึงควรเปิดใช้เฉพาะในเครื่องตัวเอง
- `--speed` ต้องมากกว่า 0 ความเร็ว 0 (เร็วสุด) ตั้งได้ผ่าน API ควบคุมการเล่นซ้ำ แต่ API จะตอบช้าลง (ราว 140 มิลลิวินาที)
- ผลการตรวจจับต้องให้คนตรวจต่อเสมอ ดู `docs/DATA_LIMITATIONS.md` และ `docs/ETHICS.md`
