# Market IDS

ระบบเฝ้าดูตลาดคริปโต แล้วเตือนเมื่อการซื้อขายดูผิดปกติทางสถิติ เช่น จำนวนการซื้อขายและราคาพุ่งขึ้นผิดธรรมชาติในเวลาสั้นๆ ซึ่งอาจเป็นสัญญาณของการปั่นราคา

ลองนึกภาพกล้องวงจรปิดของตลาด กล้องไม่ได้จับคนร้าย แต่บอกว่า "ช่วงเวลานี้แปลกนะ ลองเข้าไปดู" พร้อมตัวเลขที่เป็นหลักฐานและคำอธิบายภาษาไทย

โครงงานนี้ทำเพื่อการศึกษาในวิชา CPE102 และใช้เฉพาะข้อมูลสาธารณะของ Binance

## ระบบนี้ไม่ทำอะไร

- ไม่ซื้อขายแทนใคร ไม่มีโค้ดส่งคำสั่งซื้อขาย และไม่ใช้ API key
- ไม่แนะนำการลงทุน และไม่ทำนายราคา
- ไม่กล่าวหาใคร การเตือนไม่ได้พิสูจน์ว่ามีการปั่นราคา เพราะข่าวใหญ่ก็ทำให้ตลาดพุ่งแบบนี้ได้

## หลักการทำงาน

ระบบเรียนรู้ก่อนว่าช่วงปกติของแต่ละเหรียญเป็นอย่างไร แล้วเทียบว่าตอนนี้ต่างจากปกติมากแค่ไหน

```text
ข้อมูลการซื้อขาย
  -> สรุปเป็นตัวเลขทุก 10 วินาที
  -> เทียบกับช่วงปกติของเหรียญนั้น
  -> ตัวตรวจจับ 3 แบบช่วยกันดู
  -> รวมคะแนนเป็นค่าเดียว แล้วเทียบกับเกณฑ์
  -> รวมช่วงที่เกินเกณฑ์ติดกันเป็นการเตือนหนึ่งครั้ง
  -> เขียนคำอธิบายภาษาไทย แล้วส่งให้หน้าจอ
```

ตัวตรวจจับ 3 แบบเก่งกันคนละด้าน

| แบบ | วิธีคิด |
|---|---|
| กฎ | จับรูปแบบที่รู้จักอยู่แล้ว เช่น จำนวนการซื้อขายพุ่งพร้อมราคาพุ่ง |
| สถิติ | จับค่าที่สูงหรือต่ำกว่าปกติมาก |
| AI | เรียนจากช่วงปกติ ถ้าเจอรูปแบบที่ไม่คุ้นก็ให้คะแนนความผิดปกติสูง |

## โหมดการใช้งาน

| โหมด | ความหมาย |
|---|---|
| สด (live) | รับข้อมูลจาก Binance แล้วตรวจแบบเรียลไทม์ |
| ย้อนดู (replay) | เล่นข้อมูลวันเก่าซ้ำเหมือนดูวิดีโอ หยุดหรือกรอได้ |
| จำลองเหตุการณ์ (Red-Team) | ใส่รูปแบบการปั่นราคาลงในข้อมูลเก่า เพื่อดูว่าระบบจับได้ไหม ทำได้เฉพาะโหมดย้อนดูหรือจำลอง ระบบจะปฏิเสธถ้าสั่งในโหมดสด |

## เริ่มใช้งานเร็ว (เดโม)

ต้องมี Python 3.13 และ [uv](https://docs.astral.sh/uv/) แล้วรันจากโฟลเดอร์ของโปรเจกต์

```bash
uv sync
uv run idsai demo-pack
uv run idsai serve --mode replay
```

1. `uv sync` ติดตั้งโปรแกรมเสริมทั้งหมด
2. `uv run idsai demo-pack` โหลดข้อมูลชุดเล็กจาก Binance Vision (วันที่มีบันทึกการปั่นราคา 3 วัน และวันปกติ 20 วันของเหรียญเดียวกัน) แล้วฝึกโมเดลเก็บไว้ที่ `data/demo/` ใช้เน็ตครั้งเดียว รันซ้ำได้ วันที่โหลดแล้วจะข้าม
3. `uv run idsai serve --mode replay` เล่นวันแรกของชุดเดโมซ้ำ เริ่ม 30 นาทีก่อนเวลาในบันทึก ที่ความเร็ว 60 เท่า แล้วเปิด API ที่ `http://127.0.0.1:8800` กด Ctrl+C เพื่อหยุด

จากนั้นเปิดหน้า Dashboard ที่ `http://127.0.0.1:8800` ในเบราว์เซอร์ มีหน้า Monitor, Alerts, Red-Team, Eval, Taxonomy และ About ปุ่มลัด: `Space` เล่น/หยุด, `1`–`6` สลับหน้า, `t` สลับธีม ผลวัดบนข้อมูลจริงดูได้ที่ `docs/REPORT.md`

## คำสั่งทั้งหมด

ทุกคำสั่งรันแบบ `uv run idsai <คำสั่ง>` ดูรายละเอียดได้ด้วย `uv run idsai <คำสั่ง> --help` ถ้าสำเร็จจะจบด้วยรหัส 0 ถ้าข้อมูลไม่พอหรือใช้คำสั่งผิดจะจบด้วยรหัส 1 พร้อมบอกว่าต้องรันอะไรต่อ

| คำสั่ง | ทำอะไร |
|---|---|
| `labels` | เขียนบันทึกเหตุการณ์ปั่นราคาจริงลงเครื่อง (Sapienza เสมอ และ Hu et al. ถ้าโหลดไฟล์ไว้แล้ว) |
| `labels --align` | ตรวจว่าเวลาในบันทึกตรงกับช่วงที่มีการซื้อขายมากที่สุดจริงไหม พิมพ์ฮิสโทแกรม ถ้าคลาดเกิน 120 วินาที (ค่ามัธยฐาน) หรือวัดไม่ได้เลย จะจบด้วยรหัส 1 |
| `download --split research` | โหลดทุกวันที่งานวิจัยต้องใช้ (วันที่มีบันทึก วันก่อนหน้า และวันปกติที่เป็นตัวเลือก) |
| `download --symbols S --days N` | โหลด N วันล่าสุดของเหรียญที่ระบุ และวันก่อนหน้าวันแรก |
| `download --symbols S --day D` | โหลดวัน D และวันก่อนหน้า |
| `train [--profile research\|live] [--seed N]` | ฝึกโมเดลและตั้งเกณฑ์การเตือน เก็บที่ `models/research/` หรือ `models/live/` |
| `eval --experiment NAME\|all --seeds 0,1,2,3,4` | รันการทดลอง บันทึกผลลง `data/research.duckdb` |
| `report` | สร้างรายงานจากการทดลองทุกครั้ง ได้ `data/report.json` และ `data/report.md` |
| `demo-pack` | สร้างชุดเดโมเล็ก (ดูด้านบน) |
| `serve --mode replay [--symbol S --day D] [--speed 60]` | เล่นข้อมูลเก่าซ้ำ ไม่ระบุวัน = เล่นชุดเดโม |
| `serve --mode live` | ตรวจแบบสด ต้องรัน `download --symbols ... --days 8` และ `train --profile live` ก่อน |

ลำดับงานวิจัยเต็มรูปแบบ: `labels` → `download --split research` → `labels --align` → `train` → `eval` → `report`

`serve` เปิดที่ `127.0.0.1` พอร์ต `8800` (เฉพาะเครื่องตัวเอง) ถ้าใช้ `--host` อื่นต้องเปิดระบบล็อกอินก่อน (ดูหัวข้อถัดไป) ไม่เช่นนั้น `serve` จะไม่ยอมเริ่ม และ API รับเฉพาะคำขอที่ส่งมาถึงชื่อ `127.0.0.1`, `localhost` หรือ host ที่ระบุเท่านั้น

## ระบบล็อกอิน

ปกติ `serve` ไม่ต้องล็อกอิน (ใช้ได้เฉพาะเครื่องตัวเอง) ถ้าจะเปิดให้เครื่องอื่นเข้า ต้องเปิดระบบล็อกอิน:

1. สร้างผู้ดูแลก่อน: `uv run idsai user add <ชื่อ> --role admin` (ระบบถามรหัสผ่านแบบซ่อน ยาวอย่างน้อย 10 ตัว ไม่รับรหัสผ่านทางบรรทัดคำสั่ง)
2. เปิดด้วย `uv run idsai serve --auth ...` หรือใส่ `auth.enabled: true` ใน `configs/default.yaml` (`--no-auth` ปิดชั่วคราว)
3. สิทธิ์มี 3 ระดับ: `viewer` ดูอย่างเดียว, `analyst` ดูและบันทึกผลการตรวจกับยิงทดสอบได้, `admin` ทำได้ทุกอย่างและดูหน้า "กิจกรรม" (บันทึกการเข้าสู่ระบบและการจัดการบัญชี)
4. จัดการบัญชี: `uv run idsai user list | add | passwd | role | disable | enable` ชื่อ `cli` และ `local` ใช้เป็นชื่อในบันทึกกิจกรรม จึงตั้งเป็นชื่อผู้ใช้ไม่ได้

บล็อก `auth:` ในไฟล์ค่าตั้ง: `enabled` (เปิด/ปิด), `cookie_secure` (ตั้งเป็น `true` เมื่อเปิดผ่าน HTTPS), `remember_days` (อายุเมื่อติ๊กจำฉัน), `session_hours` (อายุปกติ) บล็อกนี้ไม่นับใน `config_hash` เพราะไม่กระทบโมเดลหรือผลการตรวจ

คำสั่ง `user` ต้องหยุด `serve` ก่อน เพราะฐานข้อมูลเปิดได้ทีละโปรแกรม ถ้า `serve` ยังรันอยู่จะขึ้นข้อความให้หยุดแล้วลองใหม่

## เปิดบนเว็บตลอด 24 ชม. (Render)

โปรเจกต์นี้เปิดเป็นเว็บบน Render (แผน Free แบบ Docker ไม่ต้องใช้บัตร) ได้ Render ดึงโค้ดจาก GitHub ไปสร้างและเปิดให้เอง และมีตัวปลุกของ GitHub Actions ทุก 10 นาที ไม่ให้เว็บหลับ ทำตามนี้ทีละข้อ:

1. เปิด neon.tech แล้วสมัครด้วยบัญชี GitHub (ไม่ต้องใส่บัตร)
2. สร้างโปรเจกต์ใหม่ แล้วเลือกภูมิภาค AWS US West (Oregon)
3. กดปุ่ม Connect หรือ Connection string แล้วคัดลอกทั้งบรรทัดที่ขึ้นต้นด้วย `postgresql://`
4. เปิด render.com กด Get Started แล้วสมัครด้วยบัญชี GitHub (ไม่ต้องใส่บัตร) อนุญาตให้ Render เข้าถึงโปรเจกต์นี้
5. กด New → Blueprint เลือก repo `IDS_AI` แล้วในหน้าเดียวกันเปลี่ยน Branch เป็น `feat/mvp` (ถ้ายังไม่ได้รวม PR เข้า `main`) เพราะ Render อ่านไฟล์ `render.yaml` จากสาขาที่เลือกในหน้านี้ ถ้าไม่เจอตัวเลือก Blueprint ให้กด New → Web Service เลือก repo เดิม ตั้ง Language เป็น Docker, Instance Type เป็น Free และตั้ง Health Check Path เป็น `/api/health`
6. ในหน้าเดียวกันกรอกตัวแปร `IDSAI_USERS` รูปแบบบรรทัดละหนึ่งบัญชี `ชื่อ:สิทธิ์:รหัสผ่าน` ช่องกรอกตอนสร้าง Blueprint อาจรับได้บรรทัดเดียว ให้ใส่บัญชี admin หนึ่งบรรทัดก่อน (รูปแบบ `ชื่อ:admin:รหัสผ่าน`) แล้วค่อยเพิ่มบัญชีอื่นทีหลังในหน้า Environment ของบริการ บัญชีละหนึ่งบรรทัด กติกา: ชื่อยาว 3–32 ตัว และห้ามใช้ `cli` หรือ `local` รหัสผ่านยาวอย่างน้อย 10 ตัว ต้องมีสิทธิ์ `admin` อย่างน้อยหนึ่งบัญชี สิทธิ์มี `viewer`, `analyst`, `admin` แล้วกรอกตัวแปร `DATABASE_URL` ด้วย connection string จากข้อ 3
7. กด Create (หรือ Apply) แล้วรอสร้างเสร็จ ครั้งแรกประมาณ 15 นาที จากนั้นเปิดที่อยู่เว็บที่ Render แสดงในหน้าบริการ แล้วเข้าสู่ระบบด้วยบัญชีจากข้อ 6
8. ที่หน้า GitHub ของโปรเจกต์ไปที่ Settings → Secrets and variables → Actions → Variables แล้วเพิ่ม variable ชื่อ `APP_URL` ค่าให้คัดลอกชื่อโฮสต์จริงจากหน้า Dashboard ของ Render (รูปแบบ `xxx.onrender.com` ไม่ต้องมี `https://`) อย่าพิมพ์เองจาก README เพราะถ้าชื่อ `market-ids` ถูกใช้ไปแล้ว Render อาจเติมตัวต่อท้ายให้
9. ทุกครั้งที่ push จะสร้างและเทรนใหม่ ใช้เวลาประมาณ 15 นาทีและกินนาทีสร้างของ Render ระหว่างที่ยัง push เข้า `feat/mvp` ให้ตั้ง Auto-Deploy เป็น "After CI checks pass" (หรือ Off) ในหน้า Settings ของบริการ ถ้าสร้างไม่ผ่านเพราะดาวน์โหลดผิดพลาด ให้กด Manual Deploy → Clear build cache & deploy
10. GitHub รันตัวปลุกตั้งเวลา (cron) จากสาขา `main` เท่านั้น จึงต้องรวม PR เข้า `main` ก่อน ระหว่างนั้นเว็บจะหลับเองหลังไม่มีคนเข้า 15 นาที และอาจใช้เวลาประมาณ 1–3 นาทีในการตื่นตอนมีคนเปิด แม้เปิดตัวปลุกแล้ว cron ของ GitHub อาจมาช้า 5–20 นาที เว็บจึงยังหลับได้บางครั้ง โปรเจกต์เป็น public จึงไม่เสียนาที Actions

โหมดเริ่มต้นของเว็บคือ live คือดูตลาดจริงแบบเรียลไทม์ ไม่ใช่ข้อมูลเก่า:

- โหมด live ติดตามเหรียญ BTC, SOL, DOGE และ PEPE จาก Binance (อ่านข้อมูลอย่างเดียว ไม่มีการส่งคำสั่งซื้อขาย)
- ใช้ 4 เหรียญ เพราะแผน Free มี RAM แค่ 512 MB ถ้าใส่ ETH เพิ่มอีกหน่วยความจำจะไม่พอ (ไฟล์ย้อนหลังอ่านทีละส่วนเพื่อประหยัดหน่วยความจำ)
- หลังดีพลอยหรือรีสตาร์ตทุกครั้ง เว็บต้องใช้เวลาประมาณ 10–20 นาทีเพื่อดาวน์โหลดและไล่ข้อมูลย้อนหลังให้ทัน แล้วแถวข้อมูลสดแถวแรกจะขึ้นหลังจากนั้นอีกประมาณ 30 นาที
- การจำลองการปั่นราคา (red-team) ใช้ได้เฉพาะโหมด replay เท่านั้น
- ถ้าเซิร์ฟเวอร์ต่อ Binance ไม่ได้ เว็บจะสลับไปโหมด replay ให้อัตโนมัติ (ดูข้อความสาเหตุในล็อก) ถ้าอยากกลับไปใช้ replay เอง ให้ตั้งตัวแปร `IDSAI_MODE=replay` ในหน้า Environment ของบริการ

ข้อควรรู้:

- โหมด replay (ตอนสลับสำรองหรือเลือกเอง) ใช้ CPU เพียง 0.1 ตัวของแผน Free การเล่นย้อนหลังจึงตั้งไว้ที่ 20 เท่า (ค่าเริ่มต้น) ถ้าจะเปลี่ยน ให้ตั้งตัวแปร `IDSAI_SPEED` ในหน้า Environment ของบริการ
- ในโหมด replay เมื่อการเล่นวนรอบใหม่ เว็บจะหยุดนิ่งประมาณ 2–3 นาทีระหว่างเตรียมข้อมูลของรอบนั้น แล้วกลับมาเดินต่อเอง
- แก้ค่า `IDSAI_USERS` เมื่อไรก็ตาม บริการจะรีสตาร์ตเอง
- รีสตาร์ตทุกครั้งจะล้างการแจ้งเตือน ผลการตรวจ (feedback) เซสชัน และบันทึกกิจกรรมทั้งหมด เริ่มใหม่จากข้อมูลเดโม ยกเว้นบัญชี ซึ่งจะคงอยู่เมื่อตั้ง `DATABASE_URL` แล้ว
- ในโหมด replay มีการเล่นย้อนหลังตัวเดียวที่ทุกคนใช้ร่วมกัน ถ้า analyst กดเล่น หยุด หรือเลื่อนเวลา ทุกคนที่เปิดอยู่จะเห็นเปลี่ยนตาม
- GitHub จะปิด workflow ที่ตั้งเวลาไว้ถ้าไม่มีความเคลื่อนไหวในโปรเจกต์นาน 60 วัน ให้เข้าแท็บ Actions แล้วกดเปิดใหม่หนึ่งครั้ง
- การสมัครบัญชีเปิดให้ทุกคนที่มีลิงก์ บัญชีที่สมัครเองได้สิทธิ์ `viewer` เสมอ
- ถ้าไม่ตั้ง `DATABASE_URL` บัญชีที่สมัครเองจะหายทุกครั้งที่รีสตาร์ต
- ถ้าสร้างบริการไปแล้วก่อนมี `DATABASE_URL` ให้ไปที่ Render → Environment เพิ่มตัวแปร `DATABASE_URL` แล้วกด Save
- บัญชีที่อยู่ใน `IDSAI_USERS` จะถูกเขียนทับรหัสผ่านและสิทธิ์จาก `IDSAI_USERS` ทุกครั้งที่บูต ดังนั้นการเปลี่ยนรหัสผ่านหรือสิทธิ์ของบัญชีเหล่านั้นในแอปจะหายไป
- การรีสตาร์ตทำให้ทุกคนต้องเข้าสู่ระบบใหม่ แต่บัญชีที่สมัครไว้ยังอยู่ ถ้าตั้ง `DATABASE_URL` แล้ว
- การลบบรรทัดออกจาก `IDSAI_USERS` ไม่ได้ลบบัญชีนั้น ถ้าต้องการเพิกถอนให้ปิดใช้งานบัญชีที่หน้า ผู้ใช้
- บัญชีใน `IDSAI_USERS` ที่ถูกปิดใช้งานในแอปจะถูกเปิดใหม่ทุกครั้งที่บูต ให้ลบบรรทัดนั้นออกจาก `IDSAI_USERS` ก่อน แล้วค่อยปิดใช้งาน

## รันชุดทดสอบ

```bash
uv run pytest
```

ชุดทดสอบไม่ใช้เน็ตและใช้เวลาหลายนาที บน Windows ควรเก็บโปรเจกต์ไว้ในโฟลเดอร์ที่ path ไม่ยาวมาก เพราะ path ที่ยาวเกิน 260 ตัวอักษรอาจทำให้เขียนไฟล์ข้อมูลหรือแคชไม่สำเร็จ

## ข้อจำกัด

- โหมดสดต้องอุ่นเครื่องก่อน แถวข้อมูลแรกมาราว 30 นาทีหลังเชื่อมต่อ ค่าเทียบกับช่วงปกติใช้ได้ทันทีถ้าข้อมูลย้อนหลังที่โหลดมายังใหม่พอ (ครอบคลุมอย่างน้อย 6 ชั่วโมงของ 24 ชั่วโมงล่าสุด) ไม่อย่างนั้นต้องรอราว 6.6 ชั่วโมง
- ระบบล็อกอินปิดอยู่โดยปริยาย ถ้าจะเปิดให้เครื่องอื่นเข้า ต้องเปิดระบบล็อกอินก่อน (ดูหัวข้อ "ระบบล็อกอิน")
- `--speed` ต้องมากกว่า 0 ความเร็ว 0 (เร็วสุด) ตั้งได้ผ่าน API ควบคุมการเล่นซ้ำ แต่ API จะตอบช้าลง (ราว 140 มิลลิวินาที)
- ผลการตรวจจับต้องให้คนตรวจต่อเสมอ ดู `docs/DATA_LIMITATIONS.md` และ `docs/ETHICS.md`
