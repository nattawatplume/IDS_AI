# Market IDS

ระบบเฝ้าดูตลาดคริปโต แล้วเตือนเมื่อการซื้อขายดูผิดปกติทางสถิติ เช่น จำนวนการซื้อขายและราคาพุ่งขึ้นผิดธรรมชาติในเวลาสั้นๆ ซึ่งอาจเป็นสัญญาณของการปั่นราคา

ลองนึกภาพกล้องวงจรปิดของตลาด กล้องไม่ได้จับคนร้าย แต่บอกว่า "ช่วงเวลานี้แปลกนะ ลองเข้าไปดู" พร้อมตัวเลขที่เป็นหลักฐานและคำอธิบายภาษาไทย

โครงงานนี้ทำเพื่อการศึกษาในวิชา CPE102 และใช้เฉพาะข้อมูลสาธารณะของ Binance

## ระบบนี้ไม่ทำอะไร

- ไม่ซื้อขายแทนใคร ไม่มีโค้ดส่งคำสั่งซื้อขาย และไม่ใช้ API key
- ไม่แนะนำการลงทุน และไม่ทำนายราคา
- ไม่กล่าวหาใคร การเตือนไม่ได้พิสูจน์ว่ามีการปั่นราคา เพราะข่าวใหญ่ก็ทำให้ตลาดพุ่งแบบนี้ได้

## หลักการทำงาน

ระบบเรียนรู้ก่อนว่าช่วงปกติของแต่ละเหรียญเป็นอย่างไร แล้วเทียบว่าตอนนี้ต่างจากปกติมากแค่ไหน

```text
ข้อมูลการซื้อขาย
  -> สรุปเป็นตัวเลขทุก 10 วินาที
  -> เทียบกับช่วงปกติของเหรียญนั้น
  -> ตัวตรวจจับ 3 แบบช่วยกันดู
  -> รวมคะแนนเป็นค่าเดียว แล้วเทียบกับเกณฑ์
  -> รวมช่วงที่เกินเกณฑ์ติดกันเป็นการเตือนหนึ่งครั้ง
  -> เขียนคำอธิบายภาษาไทย แล้วส่งให้หน้าจอ
```

ตัวตรวจจับ 3 แบบเก่งกันคนละด้าน

| แบบ | วิธีคิด |
|---|---|
| กฎ | จับรูปแบบที่รู้จักอยู่แล้ว เช่น จำนวนการซื้อขายพุ่งพร้อมราคาพุ่ง |
| สถิติ | จับค่าที่สูงหรือต่ำกว่าปกติมาก |
| AI | เรียนจากช่วงปกติ ถ้าเจอรูปแบบที่ไม่คุ้นก็ให้คะแนนความผิดปกติสูง |

## โหมดการใช้งาน

| โหมด | ความหมาย |
|---|---|
| สด (live) | รับข้อมูลจาก Binance แล้วตรวจแบบเรียลไทม์ |
| ย้อนดู (replay) | เล่นข้อมูลวันเก่าซ้ำเหมือนดูวิดีโอ หยุดหรือกรอได้ |
| จำลองเหตุการณ์ (Red-Team) | ใส่รูปแบบการปั่นราคาลงในข้อมูลเก่า เพื่อดูว่าระบบจับได้ไหม ทำได้เฉพาะโหมดย้อนดูหรือจำลอง ระบบจะปฏิเสธถ้าสั่งในโหมดสด |

## สถานะตอนนี้

| ส่วน | สถานะ |
|---|---|
| ระบบหลังบ้าน: รับข้อมูล ตรวจจับ AI การวัดผล คำอธิบาย และ API | เสร็จแล้ว |
| คำสั่งใช้งาน เดโม เอกสารการใช้งาน และระบบตรวจอัตโนมัติ | ยังไม่ทำ |
| หน้า Dashboard | ยังไม่ทำ |
| รันกับข้อมูลจริงเต็มรูปแบบและรายงานผล | ยังไม่ทำ |

ตอนนี้ยังไม่มีคำสั่งเดียวที่เปิดใช้ทั้งระบบได้ และยังไม่มีตัวเลขผลการตรวจจับบนข้อมูลจริงแบบเต็มรูปแบบ สิ่งที่ทำได้ตอนนี้คือติดตั้งและรันชุดทดสอบ

## ติดตั้งและรันชุดทดสอบ

ต้องมี Python 3.13 และ [uv](https://docs.astral.sh/uv/)

```bash
uv sync
```

```bash
uv run pytest
```

ชุดทดสอบใช้เวลาหลายนาที บน Windows ควรเก็บโปรเจกต์ไว้ในโฟลเดอร์ที่ path ไม่ยาวมาก เพราะ path ที่ยาวเกินไปอาจทำให้เขียนไฟล์แคชไม่สำเร็จ

## ไฟล์ไหนทำอะไร

### ภาพรวม

| โฟลเดอร์หรือไฟล์ | หน้าที่ |
|---|---|
| `idsai/` | โค้ดหลักของระบบ |
| `configs/` | ค่าตั้งต่างๆ แก้ได้โดยไม่ต้องแก้โค้ด |
| `tests/` | ชุดทดสอบ แยกโฟลเดอร์ตามส่วนของระบบ |
| `scripts/fetch_labels.py` | โหลดข้อมูลเหตุการณ์ปั่นราคาที่มีการบันทึกไว้ เพื่อใช้วัดผล |
| `docs/superpowers/` | เอกสารออกแบบและแผนงาน |
| `pyproject.toml`, `uv.lock` | รายการโปรแกรมเสริมที่โปรเจกต์ต้องใช้ |

### `configs/` ค่าตั้ง

| ไฟล์ | หน้าที่ |
|---|---|
| `default.yaml` | ค่าตั้งหลักของระบบ |
| `signatures.yaml` | กฎที่ตัวตรวจจับแบบกฎใช้ |
| `scenarios.yaml` | ช่วงค่าของเหตุการณ์จำลอง |
| `splits.yaml` | แบ่งช่วงวันที่ใช้ฝึกและวัดผล |

### `idsai/data/` รับและเก็บข้อมูล

| ไฟล์ | หน้าที่ |
|---|---|
| `archive.py` | โหลดข้อมูลย้อนหลังจาก Binance และตรวจว่าไฟล์ไม่เสีย |
| `live.py` | รับข้อมูลสด จัดการเมื่อเน็ตหลุด ข้อมูลซ้ำ หรือเครื่องค้าง |
| `replay.py` | เล่นข้อมูลเก่าซ้ำเหมือนเครื่องย้อนเวลา |
| `store.py` | เก็บการซื้อขาย การเตือน และความเห็นของผู้ใช้ลงเครื่อง |

### `idsai/detection/` ตรวจหาความผิดปกติ

| ไฟล์ | หน้าที่ |
|---|---|
| `features/` | แปลงการซื้อขายดิบเป็นตัวเลขสรุป เช่น จำนวนการซื้อขายและการเปลี่ยนแปลงของราคา |
| `rules.py` | ตัวตรวจจับแบบกฎ |
| `stats.py` | ตัวตรวจจับแบบสถิติ |
| `registry.py` | รวมรายชื่อตัวตรวจจับ เพื่อเรียกใช้จากที่เดียว |
| `taxonomy.py`, `taxonomy.yaml` | รายชื่อรูปแบบความผิดปกติ พร้อมคำอธิบายภาษาไทย |
| `simulator/inject.py` | ใส่เหตุการณ์จำลองลงในข้อมูลเก่า |
| `simulator/scenarios.py` | กำหนดและสุ่มเหตุการณ์จำลอง |
| `simulator/guard.py` | ด่านกันไม่ให้ใส่เหตุการณ์จำลองลงในข้อมูลสด |

### `idsai/ai/` ส่วน AI

| ไฟล์ | หน้าที่ |
|---|---|
| `autoencoder.py` | โมเดล AI ที่เรียนรูปแบบของช่วงปกติ |
| `baselines.py` | วิธีอื่นไว้เทียบ เพื่อดูว่า AI ดีกว่าจริงไหม |
| `chief.py` | "หัวหน้า" ที่รวมคะแนนจากทุกตัวตรวจจับ แล้วตัดสินว่าจะเตือนหรือไม่ |
| `learning.py` | เก็บโมเดลแต่ละรุ่น และเทียบว่ารุ่นใหม่ควรมาแทนรุ่นเก่าไหม |
| `auditor.py` | ตรวจสุขภาพของระบบเอง เช่น เตือนบ่อยเกินไปหรือช้าเกินไปไหม |

### `idsai/pipeline/` สายการทำงาน

| ไฟล์ | หน้าที่ |
|---|---|
| `batch.py` | ประมวลผลข้อมูลทีละวัน ใช้ตอนฝึกและวัดผล |
| `stream.py` | ประมวลผลต่อเนื่องทีละรายการ ใช้ตอนดูสดและย้อนดู |

### `idsai/eval/` วัดผล

| ไฟล์ | หน้าที่ |
|---|---|
| `labels.py` | อ่านข้อมูลเหตุการณ์ปั่นราคาที่บันทึกไว้จาก Telegram |
| `data/pump_telegram.csv` | ข้อมูลเหตุการณ์ดังกล่าว |
| `splits.py` | แบ่งข้อมูลตามเวลา เพื่อไม่ให้ระบบเห็นอนาคตตอนฝึก |
| `metrics.py` | คำนวณว่าจับได้กี่เหตุการณ์และเตือนผิดบ่อยแค่ไหน |
| `experiments.py` | รันการทดลองตามชุดที่กำหนด |
| `report.py` | สร้างรายงานจากการทดลองทุกครั้งที่บันทึกไว้ ไม่เลือกเฉพาะผลที่ดี |

### `idsai/product/` ส่วนที่ผู้ใช้เห็น

| ไฟล์ | หน้าที่ |
|---|---|
| `explainer/template.py` | เขียนคำอธิบายการเตือนเป็นภาษาไทย และตรวจว่าตัวเลขตรงกับหลักฐาน |
| `api/app.py` | ช่องทางให้หน้าจอขอข้อมูลและรับการอัปเดตแบบสด |
| `api/state.py` | ข้อมูลที่ API ใช้ร่วมกัน และรายงานสุขภาพของระบบ |

### ไฟล์กลาง

| ไฟล์ | หน้าที่ |
|---|---|
| `idsai/config.py` | อ่านและตรวจค่าตั้งจาก `configs/` |
| `idsai/bus.py` | ส่งข่าวสารภายในโปรแกรม จากส่วนประมวลผลไปยัง API |
| `idsai/contracts/` | กำหนดรูปแบบข้อมูลกลาง เช่น การเตือนต้องมีข้อมูลอะไรบ้าง ทุกส่วนจึงเข้าใจตรงกัน |

## ข้อจำกัด

- โหมดสดต้องอุ่นเครื่องก่อน แถวข้อมูลแรกมาราว 30 นาทีหลังเริ่ม และการเทียบกับช่วงปกติใช้ได้จริงหลังราว 6.6 ชั่วโมง
- API ไม่มีระบบล็อกอิน จึงควรเปิดใช้เฉพาะในเครื่องตัวเอง
- ผลการตรวจจับต้องให้คนตรวจต่อเสมอ
