# Hosting on Hugging Face Spaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the Market IDS dashboard 24/7 from a Hugging Face Docker Space in replay mode, with sign-in, accounts from a secret, a looping replay, and GitHub workflows that deploy the Space and keep it awake.

**Architecture:**
- The image builds the demo pack at build time from the public archive, so it carries no Hu labels and nothing from `data/`.
- At boot, a start script seeds accounts from `IDSAI_USERS`, then runs `idsai serve` with three new flags: `--public-host`, `--secure-cookies` and `--loop`.
- The loop is a serve-side wrapper. It restarts a fresh `Replayer` on the original trades with a seek to the start, so the pipeline's existing seek path resets its state and alerts.

**Tech Stack:** Python 3.13, uv, FastAPI/uvicorn, DuckDB, vanilla JS, Docker, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-05-hosting-design.md`

## Global Constraints

- **Language:** all user-facing CLI and API messages are Thai. Never print or log a password or a token.
- **Space:** port 7860, non-root uid 1000, working directory `/home/user/app`.
- **Seed format:** `IDSAI_USERS` has one `name:role:password` per line, split on the first two `:`. Blank lines and lines starting with `#` are skipped. At least one admin is required, and nothing is written if any line is bad.
- **Hardening values:** login waiter cap 16 (a 429 with "ระบบไม่ว่าง ลองใหม่อีกครั้ง"), WebSocket session re-check every 60 s (close 4401), keep-awake cron `0 */6 * * *`.
- **Data hygiene:** the image and the Space repo never contain `data/`, `models/`, `*.duckdb*` or `hu_pd_logs.tsv`.
- **Existing rules:**
  - Local `serve` on 127.0.0.1 behaves exactly as today when no new flag is given.
  - `--loop` is replay-only.
  - `auth` stays out of `config_hash`.
- **Gates:** `uv run ruff check .` is clean and `uv run pytest -q -m "not network and not slow"` passes before each commit.
- **Windows:** never pass a long `--basetemp` to pytest. Tests never touch the real `data/app.duckdb`, and test passwords are generated inside the test.
- **Commits:** every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never `git add -f`; never commit `.claude/`, `data/` or `models/`.

## Review Focus

1. **A password containing `:`, spaces or Thai characters** in `IDSAI_USERS` must seed correctly (Task 1 test `test_seed_password_with_colon_and_thai`).
2. **Windows line endings** (`\r\n`) in `IDSAI_USERS`, pasted from a Windows editor, must not end up in the password (Task 1 test `test_seed_crlf`).
3. **A mixed-case `SPACE_HOST`, or a Host header with `:443`,** must still pass the Host allowlist (Task 2 test `test_public_host_case_and_port`).
4. **The replay ending while paused, or right after a Red-Team inject,** must still loop. The run list must not show a run stuck at "waiting" forever (Task 3 tests `test_loop_restarts_after_inject` and the web test `replay_restarted marks runs missed`).
5. **A WebSocket open on a session whose user is disabled** by a re-seed after a restart must close with 4401 within 60 s (Task 4 test `test_ws_closes_when_user_disabled`).

### Task 3: Replay loop

**Files:**
- Modify `idsai/cli.py`, in `prepare_replay` (lines 799–837). It returns a looping background when `args.loop` is set.
- Modify `idsai/product/web/app.js`, in `onAlert` (line 979). Handle `{"event": "replay_restarted"}`.
- Test:
  - `tests/test_cli_hosting.py`, extended;
  - `tests/product/test_web_static.py`, extended, using its node harness.

**Interfaces:**
- Consumes:
  - `Replayer(trades, speed=..., start_us=..., preroll_from_us=...)`, together with `.seek(t)`, `.ended` and `.set_speed`;
  - `StreamPipeline.run(source)`, which returns when the source ends;
  - the pipeline's seek handling, which publishes `{"event": "alerts_reset", "t_us", "deleted"}` on bus topic `alerts` and deletes replay alerts at or after the target;
  - `AppState.replayer` and `AppState.injected`. Routes read `state.replayer` on every call, so swapping it is enough.
- Produces:
  - `looping(state, pipeline, make_replayer: Callable[[float], Replayer], start_us: int) -> Callable[[], Coroutine]` in `idsai/cli.py`. Each round awaits `pipeline.run(rp)` until it ends. It then builds a new replayer at the old replayer's speed and calls `rp.seek(start_us)`, so the first event is `("seek", start)`. It sets `state.replayer = rp` and clears `state.injected`. It publishes `{"event": "replay_restarted", "t_us": start_us}` on `pipeline.bus` topic `alerts`, then loops. Add a read-only `speed` property to `Replayer` if none exists.
  - The web side: on `replay_restarted`, every run in `state.injections` that is not `detected` gets `run.restarted = true`. `injectionStatus` returns `"missed"` for such runs, and the status text reads "พลาด (replay เริ่มใหม่)".

- [ ] **Step 1: Write the failing tests.**
  - `test_loop_restarts`:
    1. Build a tiny trades frame with `tests/synth.py` helpers, at about 3 min of trades and speed 0.
    2. Wrap `pipeline.run` with a counting fake that iterates the source to its end, and stop the background after the third round by cancelling.
    3. Assert that `state.replayer` is a new object each round and that the first event of rounds 2 and up is `("seek", start)`.
    4. Assert that `replay_restarted` was published.
  - `test_loop_restarts_after_inject`: inject into round 1's replayer, then in round 2 the trades equal the original frame (row count) and `state.injected == []`.
  - `test_no_loop_unchanged`: without `--loop`, the background is `pipeline.run(replayer)` once, as today.
  - The web test `replay_restarted marks runs missed`: a pending run plus the event gives status `missed` and the text containing `เริ่มใหม่`; a detected run stays `detected`.
- [ ] **Step 2: Run the tests.** Run `uv run pytest tests/test_cli_hosting.py tests/product/test_web_static.py -q`. They should FAIL.
- [ ] **Step 3: Implement `looping`, the Replayer `speed` property and the web handling.**
