# Sign-in, Roles and Per-user Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add admin-created accounts with roles viewer < analyst < admin, cookie sessions with 30-day "remember me", per-user settings and an audit log. Auth is off by default on loopback and required on any other bind.

**Architecture:**
- A new `idsai/product/auth.py` holds the pure parts: hashing, tokens, roles and the rate limiter.
- `Store` gains four tables with small methods.
- FastAPI gets a `current_user` dependency and a `require(role)` factory applied to existing routes, plus new auth routes.
- The serve command refuses unsafe combinations.
- The web app gains a sign-in page, a user chip, role gating, prefs sync and an Activity page, built in the redesign's look.

**Tech Stack:** Python 3.13 stdlib (`hashlib.scrypt`, `secrets`, `hmac`, `getpass`), FastAPI/Starlette, DuckDB, pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-05-auth-design.md` (runs after `docs/superpowers/plans/2026-11-05-dashboard-redesign.md`)

## Global Constraints

- **No new dependencies.** Hash format: `scrypt$n=16384,r=8,p=1$<salt b64>$<hash b64>`, with a 16-byte salt.
- **Validation rules:**
  - username `^[a-z0-9_.-]{3,32}$`
  - display name at most 64 characters
  - password at least 10 characters
- **Cookie:** named `idsai_session`.
  - Flags: `HttpOnly`, `SameSite=Strict` and `Path=/`, plus `Secure` only when `auth.cookie_secure`.
  - Remember: `Max-Age` 30 days and server expiry now + `remember_days`. Otherwise a session cookie with server expiry now + `session_hours` (12).
- **Stored token:** the DB keeps only `sha256(token)` hex. Raw tokens and passwords are never logged, stored or returned.
- **Login failure:** one generic message, `ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง`. The lock is 5 failures per username within 600 s, then a 60 s lock, held in memory.
- **Status codes:**
  - 401 `กรุณาเข้าสู่ระบบ` when there is no valid session.
  - 403 `สิทธิ์ไม่พอ (ต้องเป็น <role>)` when the role is too low.
  - WS without a session closes with code 4401.
- **Auth off:** every request is user `local` with role admin. The existing API tests must pass unchanged.
- **Serve guard:** refuse a bind outside `LOOPBACK_BINDS` when auth is off. With auth on and no enabled admin, refuse to start.
- **Prefs whitelist:** `theme ∈ {dark,light,auto}`, `symbol ∈ served symbols`, `eval_budget ∈ {0.1,0.5,2,10}`. Anything else gets 422.
- **Audit actions:**
  - `login`, `login_failed`, `logout`;
  - `feedback`, `replay_control`, `redteam_inject`;
  - `user_add`, `user_role`, `user_disable`, `user_enable`, `user_passwd`.
- **Personal data:** no email and no personal data beyond username and display name.
- **Commits:** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Same user, mixed case or spaces.** `" Alice "` must not create a second account next to `alice`. The CLI rejects it with the validation message (Task 3).
2. **Clock or expiry edge.** A session whose `expires_us` equals now is expired, and a request with it gets 401, not 200 (Task 2).
3. **Role demoted mid-session.** After `user role bob viewer`, bob's next POST must be 403 without signing in again (Task 4).
4. **Two tabs, one logs out.** The other tab's next request gets 401, the page returns to sign-in, and the hash it was on comes back after sign-in (Task 5).
5. **Login by timing.** An unknown user still runs one scrypt against a dummy hash, so the response time does not reveal which usernames exist (Task 1).

### Task 1: `auth.py` core

**Files:**
- Create: `idsai/product/auth.py`
- Test: `tests/product/test_auth_core.py`

**Interfaces:**
- Produces:
  - `ROLES = ("viewer", "analyst", "admin")`
  - `role_at_least(role: str, need: str) -> bool`
  - `hash_password(pw: str) -> str`
  - `verify_password(pw: str, stored: str) -> bool` uses `hmac.compare_digest`.
  - `verify_or_dummy(pw: str, stored: str | None) -> bool` runs scrypt against a fixed dummy hash when `stored is None`, then returns False.
  - `check_username(u: str) -> str` raises `ValueError` with a Thai message, and returns `u` unchanged when valid. It does not normalise.
  - `check_password(pw: str) -> None` raises `ValueError` when the password has fewer than 10 characters.
  - `new_token() -> str` returns `secrets.token_urlsafe(32)`.
  - `token_hash(t: str) -> str` returns the sha256 hex.
  - `class LoginLimiter(max_fail=5, window_s=600, lock_s=60, clock=time.monotonic)` with methods `locked(username) -> bool`, `fail(username) -> None` and `ok(username) -> None` (which clears the count).

### Task 2: Store tables and methods

**Files:**
- Modify: `idsai/data/store.py` (`_create_tables` plus new methods)
- Test: `tests/data/test_store_auth.py`

**Interfaces:**
- Consumes: `token_hash` and `ROLES` (Task 1).
- Produces, as `Store` methods. Each takes `self._lock` and uses `self._db()` like the existing methods. Times are `us: int`.
  - `add_user(username, display_name, role, pw_hash, now_us) -> str` returns `user_id` (uuid4 hex) and raises `ValueError` if the name is taken.
  - `get_user_by_name(username) -> dict | None`
  - `get_user(user_id) -> dict | None`
  - `list_users() -> list[dict]` never includes `pw_hash`.
  - `set_role(username, role) -> None`
  - `set_disabled(username, flag: bool) -> None` deletes that user's sessions when disabling.
  - `set_password(username, pw_hash) -> None` deletes that user's sessions.
  - `has_enabled_admin() -> bool`
  - `create_session(user_id, token_h, now_us, expires_us, remember) -> None`
  - `get_session(token_h, now_us) -> dict | None` returns None if `expires_us <= now_us` or the user is disabled. It joins the users table and returns `{user_id, username, display_name, role, remember, last_seen_us}`.
  - `touch_session(token_h, now_us) -> None`
  - `delete_session(token_h) -> None`
  - `purge_sessions(now_us) -> int`
  - `get_prefs(user_id) -> dict`
  - `set_prefs(user_id, prefs: dict) -> None`
  - `add_audit(now_us, user_id, username, action, target="", detail: dict | None = None) -> None`
  - `list_audit(limit=200, before_us: int | None = None) -> list[dict]` is newest first and caps the limit at 500.

**Files:**

- Modify: `idsai/cli.py`: pass `auth_enabled` into `AppState`, and purge expired sessions at startup and hourly in the background task.
- Test: `tests/product/test_api_auth.py`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces in `app.py`:
  - `LOCAL_USER = {"user_id": "local", "username": "local", "display_name": "local", "role": "admin"}`
  - `async def current_user(conn: HTTPConnection) -> dict` returns `LOCAL_USER` when auth is off. Otherwise it reads the cookie, then `store.get_session`, then `touch_session` if the last touch is older than 60 s; with no session it raises 401.
  - `def require(role: str)` returns a dependency giving the user, or raising 403.
  - Routes:
    - `POST /api/auth/login`: body `LoginIn(username, password, remember: bool = False)`.
    - `POST /api/auth/logout` returns 204.
    - `GET /api/me` returns `{username, display_name, role, auth_enabled, prefs}`.
    - `PUT /api/me/prefs`: body `PrefsIn` is the whitelist, with `extra="forbid"`.
    - `GET /api/audit?limit&before_us` requires admin.
  - Gates:
    - every existing GET route and the WS use `current_user`;
    - feedback, replay control and inject use `require("analyst")`;
    - `/api/health` stays public.
  - Feedback stores `user["username"]` as the analyst.
  - Audit is written for login, login_failed, logout, feedback (`{"verdict"}`), replay_control (`{"action","value"}`) and redteam_inject (`{"family","region","symbol"}`).
